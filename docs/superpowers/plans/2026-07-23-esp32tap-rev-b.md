# Esp32Tap Rev B Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` to implement this plan task by
> task, and `superpowers:test-driven-development` for every source change.
> Project tracking remains in beads (`precor-9_3x-cyq`,
> `precor-9_3x-4py`, `precor-9_3x-0k8`, `precor-9_3x-8bw`, and
> `precor-9_3x-bkf`); numbered steps replace Markdown checkboxes because
> this repository's `AGENTS.md` forbids Markdown TODO lists.

**Goal:** Produce a reproducible Esp32Tap Rev B schematic, four-layer PCB,
fabrication package, enclosure, safety contract, and dual-ngspice evidence
that implement the approved treadmill-powered, fail-to-bypass architecture.

**Architecture:** `hardware/Esp32Tap/tools/design.py` remains the electrical
source of truth. Generators derive the schematic, board, BOM, placement, and
fabrication outputs; committed validators independently compare those
artifacts back to the design tables. Behavioral ngspice decks prove only
their documented electrical assumptions, while physical and vendor-only
questions remain explicit HOLD gates.

**Tech Stack:** Python 3.12, pytest 8, KiCad/pcbnew 10.0.1, ngspice 42,
Dockerized ngspice 39, OpenSCAD 2021.01 in Docker, trimesh, JLCPCB Standard
four-layer fabrication.

## Source and artifact map

- `hardware/Esp32Tap/tools/design.py`: component metadata, pad maps, nets,
  DNP set, pin electrical types, and design-level invariants.
- `hardware/Esp32Tap/tools/gen_sch.py`: generated typed Rev B schematic and
  symbol library.
- `hardware/Esp32Tap/tools/gen_pcb.py`: generated 100 mm × 55 mm, four-layer
  placement, routing, planes, keepouts, and silkscreen.
- `hardware/Esp32Tap/tools/gen_docs.py`: generated NETLIST, BOM, and CPL with
  correct DNP handling.
- `hardware/Esp32Tap/tools/inspect_kicad.py`: `/usr/bin/python3`/pcbnew
  inspection process that emits versioned JSON and has no pytest/trimesh
  dependency.
- `hardware/Esp32Tap/tools/validate_artifacts.py`: default-Python audit that
  consumes the inspector JSON and independently checks schematic, PCB,
  BOM/CPL, USB, stackup, test access, and the fab package.
- `hardware/Esp32Tap/tools/export_fab.py`: clean-directory KiCad export and
  deterministic archive construction.
- `hardware/Esp32Tap/tests/`: test-first design, generator, artifact,
  simulation-runner, documentation, and enclosure checks.
- `hardware/Esp32Tap/sim/`: seven committed behavioral decks, assertion
  manifest, dual-engine runner, and limitations.
- `hardware/Esp32Tap/enclosure/`: corrected SCAD, generated STLs, dimensions,
  and independent mesh/fit validator.
- `hardware/Esp32Tap/firmware/PLAN.md`: normative Rev B firmware safety
  contract; this is a plan, not a claim that firmware exists.
- `hardware/Esp32Tap/firmware/safety_model.py`: executable host reference
  model for lease, freshness, relay, and fault behavior; not production
  ESP-IDF firmware.
- `hardware/Esp32Tap/{README,REPORT,VALIDATION,WORKS-AND-FITS,ORDERING,ORDER-READY,AI-HANDOFF,PREFAB-ADVICE-FOR-CLAUDE}.md`:
  status and handoff documents. They must never outrun the evidence.
- `hardware/Esp32Tap/Makefile`: canonical non-hardware `test`, `generate`,
  `erc`, `drc`, `sim`, `enclosure`, `fab`, `check`, and `clean-check`
  entry points.
